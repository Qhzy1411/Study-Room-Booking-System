# 智慧自习室预约与管理系统 · 交接文档

## 1. 项目概况

项目是一套可运行的 Node.js 单体应用（Express 5 + Node 内置 SQLite），实现了需求规格中的认证权限、资源与开放计划、预约互斥与幂等、签到/暂离/签退/到期、停用、违规复核、限制、投诉、评价、通知、故障纠正、统计、到座导览、推荐、现场问题与换座等业务；内置可复现的演示数据与演示时钟。前端为无构建步骤的原生 ES Modules SPA，包含登录、学生端七页与管理端五页，提供座位图、路线图和扫码组件。

测试使用 **pnpm + Vitest**：`tests/unit/server`（真实 HTTP + 临时 SQLite）、`tests/unit/client`（happy-dom）、`tests/e2e`（playwright-core 驱动本机 Chrome/Edge）。

## 2. 快速开始

```bash
pnpm install
pnpm start          # 默认 http://127.0.0.1:3000

pnpm test           # 全量测试（单元 + API + 浏览器冒烟）
pnpm test:unit      # 仅单元/API
pnpm test:e2e       # 仅浏览器端到端
pnpm test:coverage  # 覆盖率报告
pnpm seed:perf      # 重置当前数据库并生成 500 座位 / 1 万预约的性能数据集
```

- 需要 **Node.js ≥ 22.5**（使用内置 `node:sqlite`；已在 Node 24.15 实测）。
- `pnpm start` 与 `pnpm run dev` 已带 `--no-warnings`，用于屏蔽 `node:sqlite` 的实验性警告。
- 启动时若数据库为空会自动 seed；`pnpm seed` 会重置全部业务数据并生成演示数据。
- 数据库文件：`data/studyroom.db`（WAL 模式）。需要保留现有数据时，先将 `DB_PATH` 指向独立测试库，再执行重置命令。
- 环境变量：`PORT`（默认 3000）、`HOST`（默认 127.0.0.1）、`DB_PATH`、`DEMO_MODE`（默认开）、`TICK_INTERVAL_MS`（默认 5000）、`QR_SECRET`。
- 测试会为每个测试文件启动独立临时数据库与随机端口，不影响 `data/studyroom.db`。

## 3. 技术架构

```
浏览器（原生 ES Modules SPA，无构建步骤）
        │  fetch /api/*（同源 Cookie 会话）
        ▼
Express 5（server/index.js）
  ├─ 会话/权限（server/auth.js）
  ├─ HTTP 路由（server/routes.js，所有接口集中在此）
  ├─ 业务服务（server/services/*.js）
  ├─ 后台任务（server/scheduler.js：到期补处理 + 站内通知投递）
  └─ SQLite（node:sqlite，同步事务）
```

- 没有 ORM、没有构建工具；后端依赖仅 `express` 与 `qrcode`。
- 预约创建、换座和停用通过 `server/db.js` 的 `tx()`（外层 `BEGIN IMMEDIATE`，嵌套 `SAVEPOINT`）。预约的冲突检查与写入在同一事务内完成。
- 时间统一存 epoch 毫秒；业务按 **Asia/Shanghai（固定 UTC+8）** 计算。预约业务的当前时间取自 `server/clock.js` 的 `now()`。
- 静态资源由 `server/index.js` 提供；非 `/api` 的 GET 回退到 `public/index.html`。
- 安全基线：scrypt 密码哈希、哈希化会话令牌、HttpOnly + SameSite=Lax Cookie、默认拒绝的权限检查、输入校验、参数化 SQL、CSP/安全响应头、登录失败限流。**本地未启用 HTTPS / Secure Cookie，部署时需补。**

**关键业务规则的实现要点**

- 区间一律半开 `[开始, 结束)`；重叠判定 `a.start < b.end && b.start < a.end`；相邻允许。
- 预约保留与登记使用使用两个分段表：`reservation_segments`、`usage_segments`。换座时旧段止于切换时刻、新段从切换时刻开始，同一时刻不重复统计。
- 幂等：`idempotency` 表与业务写入同事务；同键不同载荷 409；响应丢失后按原键查询返回原结果。
- 额度：按预约**开始日期**统计，排除 `waived=1` 的场地免责记录；时长按实际占用计算（本人取消返还时长、提前签退按签到至签退的实际分钟数，次数仍计入）。
- 签到窗口：`[开始, min(开始+宽限, 结束))`；无占座保护且到截止未签到时转爽约并生成 `no_show:<预约号>` 唯一事件。 占座报告在原截止前受理，且预约仍在报告座位待签到时，可获得一次限时保护；保护到期仍未签到则免罚释放。
- 暂离：最晚返回 `min(暂离开始+15min, 预约结束)`；截止早于结束 → 异常关闭；相等 → 到期完成。
- 停用：先预览影响并返回 `impactHash`；提交时重算影响集合，变化则 409；立即停用使用中/暂离中座位需 `cleared=true`；待签到受影响预约按场地原因免罚取消。
- 违规：待复核 → 生效/撤销；生效记录可撤销；依据全部撤销时关联限制自动解除；签到故障登记自动撤销截止落在故障区间的爽约事件。
- 统计：可用座位分钟 = 逐座位按创建/归档/恢复的生效区间计算开放分钟 − 停用并集；事后增减座位不会改写历史日期的分母。预约创建量、签到量、爽约事件和取消量按所选统计时段的事件发生时刻统计，不受开放时段裁剪；开馆前创建的预约也计入创建当天。统计卡片与柱状图使用同一日期和所选时段。登记使用分钟来自使用分段（暂离期间无使用分段），分母为 0 显示“—”，一位小数。
- 地图：通道多边形/折线构图，座位不可作为通路；从入口到座位前缘 Dijkstra；地图版本写入 `route_views`。
- 推荐：必要条件（开放、无停用、无冲突、必要设施正常）先过滤；“靠窗/近入口”只影响排序，同分按座位号；无结果不放宽。

主要状态码：400 输入、401 未登录、403 越权/回避/禁用、404 不存在、409 冲突/幂等键复用/影响集合变化、422 业务规则不满足、429 登录限流。

## 6. 数据库要点

`server/db.js` 启动时自动建表。核心表：

- 用户与授权：`users`、`sessions`、`room_grants`、`business_permissions`、`rule_versions`
- 资源：`rooms`、`seats`、`facilities`、`facility_history`、`room_maps`、`open_plans`、`open_plan_history`、`suspensions`
- 预约：`reservations`、`reservation_segments`、`usage_segments`、`checkins`、`away_records`、`seat_changes`、`route_views`
- 治理：`violations`、`limits`、`limit_basis`、`complaints`、`complaint_events`、`evaluations`、`evaluation_history`、`faults`
- 支撑：`notifications`、`audits`、`idempotency`、`meta`（计数器、演示时钟偏移）

约定：

- 业务编号：`RSV-0001`、`V-0001`、`L-0001`、`C-0001`、`SUS-0001`、`F-0001`、`SC-0001`、`EV-0001`。
- 预约状态：`pending / using / away / cancelled / completed / no_show / aborted`。
- 投诉状态：`pending / processing / answered / closed`；现场问题复用同一状态机（`is_site=1`）。
- 违规状态：`pending / effective / revoked`。
- 所有审计与业务同事务；审计写入失败则业务失败。
- 通知按 `(user_id, event_key)` 唯一。

## 8. 前端设计基线

- 视觉：浅灰背景、白色卡片、蓝色主色 `#2457d6`、16px 圆角、轻阴影；中文系统字体。
- 布局：顶部栏（品牌、业务时钟、通知铃铛、用户菜单）+ 左侧分组导航；≤900px 侧栏变为横向滚动导航；≤640px 单列。
- 登录页：左右分栏，左侧渐变品牌面板与三条价值点，右侧表单；底部演示账号快捷填充（登录一次进入对应角色）。
- 学生导航：预约座位、我的预约、到座导航、投诉与申诉、通知、违约与限制、个人资料。
- 管理导航：场地管理（座位设施/开放计划/停用/二维码/现场预约）、违约与限制、投诉处理、数据统计、系统管理（账号角色/规则/审计/通知投递/演示时钟，仅系统管理员）。
- 共用组件：`toast`、`openModal`、`confirmDialog`、`promptDialog`、`statusBadge`、`emptyState`、座位图、路线图、图表、扫码对话框。
- 隐私与安全：前端只渲染后端返回的本人/授权数据；不使用 `innerHTML` 插入用户输入（图标常量除外）。

### 页面关键交互

- 预约页：切换日期/时间/必要条件/入口/偏好会自动重新查询；座位状态颜色 + 文字 + `aria-label`；选中座位失效时清除并提示；提交按钮要求勾选规则；成功弹窗展示预约号、签到截止与规则版本。

## 9. 已知问题与运行边界

- 停用重复提交时，若使用新的幂等键，仍可再次创建重叠停用安排（不影响可用性，但会产生多条安排）。前端复用同一操作键直到结果明确。
- 通知投递失败支持系统管理员注入/重试与手动 tick，没有自动重试队列。
- 演示账号 S1 已授予规则、审计、业务复核与统计权限；新建的系统管理员默认无业务权限，可在“账号与授权”中分配。
- 系统管理员默认无场地授权，因此 `/api/admin/rooms/:roomId` 对 S1 返回 403。
- 现场问题中的“座位被占用”在 `complaints.type` 中复用 `service`（表结构约束只有 facility/service/appeal）；占座标识另存于 `complaints.is_occupancy`。
- 预约详情的历史时间文本依赖服务端 DTO；不要在前端用 `new Date(ts).toLocaleString()`（浏览器时区可能不是北京时间）。
- 演示时钟偏移持久化在 `meta`，重启后仍生效；`pnpm seed` 会恢复真实时间。
- 会话 Cookie 未加 `Secure`；生产部署必须启用 HTTPS 并改为 Secure，同时考虑 CSRF 令牌（当前依赖 SameSite=Lax 与 JSON 请求）。会话过期按真实时间而非业务时钟计算，避免演示时钟影响登录。
- 登录限流在内存中，重启清零；多实例部署需要外部存储。
- 静态二维码 + `GET /reservations/:id/desk-code` 便于相机不可用时手动签到，但静态码本身不防代签（需求明确不把静态码作为防代签证明）。
- `node:sqlite` 在 Node 24 仍标记实验性；升级 Node 时需回归。
- 统计接口为同步计算。
- 无真实数据留存/匿名化策略；本期只使用合成数据。
- 房间的新建/归档没有 API（只有座位创建/归档）。
- 预约提醒（开始前 30 分钟）已由后台任务生成；通知开关按用户偏好生效。
- 管理端投诉升级（无回避处理人时转业务授权系统管理员）没有专门流程，依赖账号授权。

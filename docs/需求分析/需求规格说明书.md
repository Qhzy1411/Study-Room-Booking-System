## 2. 项目概述

### 2.1 研发背景

本项目的核心价值是让学生不仅能够预约座位，还能找到符合使用需要的座位、顺利到达，并在座位被占用或设施故障时获得可执行的处理方案。

#### 2.1.1 技术痛点

经过深入调研，我们了解到现有智慧自习室预约与管理系统存在以下问题。



| 问题及依据 | 需要解决的技术问题 | 本项目的改进机制 |
|---|---|---|
| 用户不熟悉馆内空间，寻找目的地困难；[温州肯恩大学读者反馈](#SRC-06) | 预约中的座位如何与楼层、入口、通道和桌椅位置对应？ | 预约直接关联目标位置，按所选入口生成路线，提供地标说明和座位核对 |
| 已预约座位被他人占用；[中国传媒大学使用通知](#SRC-07) | 预约有效但现场无法使用时，如何协调处理并保留预约者已有权益？ | 问题自动关联预约凭证，显示处理进度，提供由学生确认的替代座位 |
| 具体座位插座故障；[南京工业大学浦江学院读者反馈](#SRC-08) | 座位空闲但设施不能使用时，如何及时影响筛选、推荐及换座？ | 管理员核实设施状态，更新必要条件匹配；维修完成后重新参与候选判断 |
| 现有使用说明区分座位位置与环境；[中国传媒大学使用通知](#SRC-07) | 多个座位均可预约时，如何表达使用条件并说明选择理由？ | 区分必须满足的设施条件与排序偏好，提供可核对的推荐理由；具体偏好由使用者选择 |



#### 2.1.2 改进机制

**预约与到座导引关联。** 系统使用当前预约的座位作为目的地，使用学生选择的入口作为起点。路线沿经核对的通道抵达目标座位，不穿越桌椅；到达后扫描桌面二维码核对座位并申请签到。地图缺失或无可达路线时提供文字位置及求助信息。学生无需在预约记录与独立地图之间反复寻找座位编号，因此有望减少首次到场的查找步骤和走错情况。本期采用二维地图与文字地标，以经核对的场地布局和合法路径支撑导引。


**设施状态与选座推荐关联。** 系统先判断时段、开放、资源冲突和必要设施，再按靠窗或通道距离等偏好排序。设施已确认故障时，不作为满足“必须可用”的候选；无匹配结果时由学生明确决定是否调整条件。管理员核实故障、登记修复后，筛选和推荐读取同一份设施状态。这种机制有望减少学生到场后才发现设施不适用的情况。

### 2.4 本期范围与需求优先级

本项目面向单校多自习室的统一预约与管理。系统按自习室组织座位、设施和开放计划，并按场地划分管理员权限。学生通过适配手机和桌面浏览器的Web应用查询、预约和使用座位；管理员通过管理页面维护资源、处理异常、受理投诉并查看统计。首期采用独立账号与站内通知；后续开发按约8周安排，分为四个两周迭代。

本期功能包括自习室和座位属性维护、开放计划、预约与取消、签到与签退、暂离与返回、自动及手动违约登记、预约和使用记录查询、用户信息管理、评价、投诉及反馈、黑名单限制和站内通知。管理员可按授权场地管理资源，并通过统计卡片、柱状图和折线图查看使用情况；统计页面每10秒自动刷新。

系统的主要改进是预约联动导引、设施条件推荐和保障原预约权益的现场换座。工程重点包括地图与资源关联、设施状态同步、换座一致性，以及支撑这些能力的预约互斥、故障纠正和可复算统计。验收使用500个座位、1万条历史预约及20个并发用户的测试规模，检查权限隔离、重叠竞争、重复请求和故障恢复；具体条件和指标见[第7章质量要求](#quality)。场地及座位由配置维护，首批部署范围可随验证结果逐步扩展。

本期同时包含预约到座导引、按必要条件和偏好推荐座位、现场问题报告、本人确认换座，以及设施状态维护和场地布局配置。新增能力在保留基础预约与管理范围的前提下实施。

本项目使用P0、P1两级需求优先级，分别表示核心必需能力和本期完善能力，两者均纳入本期交付。优先级用于确定实施顺序，具体安排见[9.2开发迭代计划](#development-plan)。

| 级别 | 本项目定义 | 对应需求及交付要求 |
|---|---|---|
| P0：核心必需 | 支撑授权访问、预约及资源使用的完整流程 | 覆盖身份权限、资源开放、预约互斥、取消、签到签退、到期处理及停用恢复，优先在第1—4周完成并持续回归 |
| P1：本期完善 | 完善使用体验、现场问题处理及运营管理 | 覆盖违规处理、用户反馈、统计、暂离，以及到座导引、设施选座和现场换座；地图数据从第1轮准备，第2—3轮完成关联功能，第4轮共同验收 |


### 2.5 范围外事项与业务边界

本期不包含收费、未经本人确认的自动换座、校园统一身份认证、蓝牙或门禁接入、连续实时定位、定位签到、物理占座识别、训练预测模型及多校多租户服务。地图采用部署前核对的二维布局与文字地标；在线地图编辑、通道开闭调整及三维场景不作为本期交付要求。桌面二维码用于识别所属场地和座位，学生扫码后，系统校验本人预约、目标座位和签到窗口，满足条件才登记签到。静态二维码不作为连续在座或防代签的证明。现场事实由管理员核实，系统保存登记及处置依据。

外部认证和消息平台不作为本期依赖；站内通知失败不撤销已经提交的业务结果。系统上下文见[系统上下文图](附件/01图模型/CTX-01-系统上下文图.svg)。

## 4. 领域与数据

### 4.1 领域术语与核心关系

| 术语 | 统一含义与边界 |
|---|---|
| 自习室与座位 | 自习室是场地管理范围，座位是预约的最小资源；房间内座位号唯一 |
| 开放计划 | 定义资源可提供服务的日期及时段；已发布版本供查询和预约校验 |
| 停用区间 | 从开放时间中排除的区间，可因检修或管理需要建立；恢复不复活已结束预约 |
| 预约保留区间 | 预约成功后排他保留的座位时间；提前释放时记录实际释放时刻，原计划仍可追溯 |
| 登记使用 | 由签到、签退和系统结束构成的业务记录；不等于传感器检测的物理在座情况 |
| 自动违约记录 | 到期未签到形成的待复核事件；不直接等同处罚或生效违规 |
| 生效违规 | 授权人员核对规则及证据后作出的复核结论；可通过申诉或故障核实纠正 |
| 黑名单限制 | 依据生效违规建立、具有场地范围和有效期限的新预约限制；不阻止签退或申诉 |
| 投诉与评价 | 投诉要求受理与答复，评价记录使用体验；二者分别管理并保留处理历史 |
| 规则版本 | 创建预约时采用的时间和额度设定；规则更新不改写旧预约所适用的版本 |
| 幂等请求 | 相同用户、操作键及载荷重复提交时返回同一业务结果；不同载荷不得复用相同键 |
| 到座导引 | 将本人当前预约座位与已核对的场地地图关联，依据所选入口及开放通道提供路线；到达后扫描桌面二维码，核对预约目标并申请签到 |
| 必要条件与偏好 | 必要条件决定座位能否入选；偏好只影响合格候选的排列顺序，无结果时不自动放宽条件 |
| 现场问题 | 与原预约和发生时座位关联的占座或设施问题，使用投诉处理状态；换座不代替原问题的核实与处理 |
| 换座与分段 | 在原预约内更换剩余时段所用座位；记录各座位的保留和登记使用区间，不新建预约或延长时段 |
| 统计快照 | 某一确定时点、授权范围及统计窗口下的统一计算结果；卡片和图表使用同一快照 |

资源关系见[资源与使用数据关系图](附件/01图模型/DM-01-资源使用领域图.svg)：一个自习室包含多个座位，一个用户可有多条预约，每条预约关联一个当前座位及一个规则版本，换座前后的资源关系由保留分段与换座记录保存；同座位和同用户的有效保留区间分别满足互斥约束。

投诉、评价和违规处理的数据关系见[反馈与违规数据关系图](附件/01图模型/DM-02-反馈治理领域图.svg)：投诉可关联预约或违规事件，违规可来自自动事件或现场登记，限制关联至少一条生效违规。每笔符合条件的预约最多一条当前评价。基础领域图共享用户和预约概念，数据属性及访问范围以数据字典为准。

领域图中，连线端点的数字表示该端对象的数量：`1`表示恰好一个，`0..*`表示零个或多个，`0..1`表示零个或一个，`1..*`表示一个或多个。例如，“用户 1 — 0..* 预约”表示每条预约属于一个用户，一个用户可有零条或多条预约。

### 4.3 统计指标与计算口径

本节规定FR-16统计卡片、柱状图和折线图的计算规则。管理员按授权自习室及当地日期查询，所有图表使用同一数据快照并显示更新时间。当天只统计快照时刻之前已经发生的使用时长，不将未来预约时长计为登记使用。

不同事件采用各自的归属时间：预约创建量按创建时刻统计，首次签到量按签到时刻统计，爽约事件按原签到截止时刻统计。三者对应的记录集合不同，不能直接相除作为同一批次转化率。取消量按取消时刻统计，并区分本人取消和场地取消；净生效违规按事件发生日及快照时的有效结论统计。

每日预约额度按预约开始日期计算，其用途是判断能否创建新预约；预约创建量用于描述系统发生过的创建活动。场地免罚处置可以返还额度，但不删除历史创建记录。

| 指标 | 口径 | 图形或展示 |
| --- | --- | --- |
| 预约创建量 | 所选统计时段内成功创建的预约数，含后来取消的记录，不重复计重试 | 统计卡片、按日期折线 |
| 首次签到量 | 首次签到时间落在所选统计时段内的预约数 | 统计卡片 |
| 爽约事件量 | 截止落在所选统计时段内且已爽约的预约数；不等于已处罚人数 | 统计卡片 |
| 净生效违规数 | 事件发生在所选统计时段内且快照时仍生效的记录数 | 统计卡片 |
| 可用座位分钟 | 逐座位计算统计时段内、快照时刻之前的开放分钟，扣除停用分钟后求和；重叠停用仅扣一次 | 使用率分母；不得重复减重叠停用 |
| 登记使用分钟 | 逐预约按使用分段计算签到至签退、到期或异常关闭的时长；换座时旧座位分段结束，新座位分段开始，同一时刻不重复计入；仍在使用的计算至快照时刻，只计可用开放时段，并扣除暂离时长 | 使用率分子 |

统计修订按事件和版本复算；不可用“当前有几人签到÷总座位数”替代上述分钟口径。计算示例见[第8.4节统计计算样例](#fixtures)，统计公式与刷新行为的验收要求见第8.3节。

### 4.4 留存、归档与历史纠正

有预约、投诉或违规记录引用的账号、座位及规则版本应保留可追溯标识。资源退出使用时归档或停用，历史预约保留原资源、时间、规则版本和处置原因，不通过删除资源消除历史记录。

违规撤销、限制解除、评价修改和投诉补充均保留前后记录及操作者；统计按最新有效结论复算，同时显示快照时间。普通业务角色不得改写审计记录。用户仅能读取本人记录或履职必需的授权范围，导出和日志不得包含密码、令牌或无关个人信息。

真实账号、预约、投诉材料及审计记录的保存期限由制度与数据管理责任人确认。本期使用合成数据；正式数据接入前应明确授权、保存期限、删除或匿名化方式以及统计保留口径。

## 5. 业务规则与权限

<a id="rules"></a>

### 5.1 规则基线

业务规则统一规定允许条件、拒绝条件、计算方法和处置结果。规则来源及确认状态见[需求分析质量验证报告 A.2节](A-需求分析质量验证报告.md#confirmation)；原规则与参数的确认记录保留；本次新增范围依据2026年10月30日小组统筹人的修订要求纳入，新增规则与验收结果分别管理。
时间比较均使用服务端判定时刻。区间[开始,结束)包含开始时刻，不包含结束时刻；例如14:00—15:00与15:00—16:00可相邻使用。

| 规则 | 主题 | 可执行定义 |
| --- | --- | --- |
| <a id="BR-01"></a>BR-01 | 资格与限制 | 仅启用账号可登录；创建预约还须无生效且覆盖目标场地的黑名单限制。限制不阻止取消、签退、查询或投诉。账号被禁用时由管理员协助结束现有使用并保留求助渠道。 |
| <a id="BR-02"></a>BR-02 | 座位时间互斥 | 所有区间采用 Asia/Shanghai 的 [开始,结束)。开始必须早于结束；重叠条件为“第一段开始早于第二段结束，且第二段开始早于第一段结束”。相邻区间允许；部分交叠、包含和完全相同均拒绝。校验与提交必须构成一个不可分割的业务操作。 |
| <a id="BR-03"></a>BR-03 | 用户时间互斥 | 同一用户在不同座位上的有效保留时段也不得重叠；已取消、已爽约、已完成或异常关闭后的剩余时段不再保留。历史原起止时间保留，另记实际释放时刻。 |
| <a id="BR-04"></a>BR-04 | 上限与版本 | 规则版本记录预约提前天数、最小时长、每日次数及累计时长上限。每日额度按预约开始日期归属，而非提交日期归属。次数统计该日成功创建的预约，时长累计对应原定分钟数；本人取消和提前签退不扣回。因场地停用而取消或关闭的预约不计入当日次数和时长额度，保留免责原因。本期预约不得跨午夜。原预约沿用创建时规则版本；新规则仅用于新预约，安全停用例外。 |
| <a id="BR-05"></a>BR-05 | 开放计划 | 预约须完整落在已发布开放区间且不与停用区间重叠。开放计划缩短若影响已有预约，拒绝直接保存，提示先通过停用流程处理；恢复/扩展开放不自动恢复旧预约。 |
| <a id="BR-06"></a>BR-06 | 签到 | 不提前签到；签到窗口从预约开始时刻起，到“开始加宽限”与“预约结束”中较早的时刻止，不包含截止时刻。占座保护期间以 BR-27 规定的保护截止为准。采用本人扫描桌面二维码申请签到，码中标识须对应有效场地与座位，且与本人当前预约一致；服务端校验身份、状态和时间后记录签到。无效码、错座、越权或过早扫码拒绝；重复有效请求返回原签到结果。现场管理员可辅助并记录核实说明；静态码不提供防代签或连续在座证明。本期不接入蓝牙或定位签到。 |
| <a id="BR-07"></a>BR-07 | 自动爽约 | 无占座保护的预约达到或超过签到截止且仍待签到，则转已爽约、释放时段并生成唯一待复核违约记录。占座保护到期和核实不属实按 BR-27 处理。待复核记录不能直接形成黑名单；系统故障相关记录须先核实。 |
| <a id="BR-08"></a>BR-08 | 取消 | 本人仅在预约开始之前且待签到时取消，已开始未签到应签到或到期处理。取消不记违约，不返还当日次数/时长额度；重复同一成功请求返回原结果。 |
| <a id="BR-09"></a>BR-09 | 暂离与返回 | 使用中且未到预约结束时允许暂离。最晚返回时间取“暂离开始加允许时长”与“预约结束”中较早者；之前允许返回。最晚返回早于预约结束且已经到达时，异常关闭并释放，不自动认定违规；两者相同时按预约到期完成。暂离期间允许签退和管理员停用关闭。 |
| <a id="BR-10"></a>BR-10 | 权限 | 默认拒绝；每个请求同时检查角色、操作、对象归属和场地范围。管理员不能仅凭知道对象编号越权。系统管理员默认只管理技术配置，获得明确业务授权后才可复核争议。 |
| <a id="BR-11"></a>BR-11 | 停用 | 停用前填写对象、开始时间、结束时间和原因，展示受影响预约及处置。结束时间必须晚于开始时间，计划开始时间不得早于当前时间；时间或原因修改后须重新预览。到达结束时间后不再阻止该停用区间之后的预约，既有取消或关闭记录保持不变。重叠的待签到预约统一按场地原因取消且免罚。立即停用影响使用中/暂离中时，管理员须先确认现场清场再异常关闭且免罚。未来停用若与正在使用或暂离的预约相交，拒绝该方案，要求调整起点或执行立即停用。提交时重新校验影响集合，变化则重新确认。 |
| <a id="BR-12"></a>BR-12 | 原子与审计 | 预约变更、停用及受影响预约、违约复核及关联限制纠正须完整成功或均不生效。必要审计随业务提交；审计写入失败则业务失败。通知独立重试。保留操作者、时间、对象、规则版本、前后值、理由、关联事件和结果，普通角色不可修改历史。 |
| <a id="BR-13"></a>BR-13 | 幂等与不确定结果 | 同用户同操作键及相同载荷返回首次结果；同键不同载荷拒绝。更换键不能绕过冲突校验。响应丢失时显示“结果待查询”，按原键查询，不能直接宣称失败。 |
| <a id="BR-14"></a>BR-14 | 时钟与竞争 | 先验证身份、操作及对象范围；不合格请求立即拒绝且不触发到期补处理。合格请求取得一致当前状态后，以服务端事务中的判定时刻为准；达到或超过截止即到期，不依赖客户端时钟。签到、签退、取消、停用及后台任务竞争时只提交一次合法状态变化。请求读取或操作前补处理到期状态；后台重试按原截止判断，不能以恢复时间替代业务发生时间。 |
| <a id="BR-15"></a>BR-15 | 签退释放 | 主动签退和到期结束均记已完成并区分结束原因；提前签退释放 [实际结束时间,原预约结束时间)。新预约仍须满足最小时长、开放和互斥规则。到期结束仅是系统登记结束，不证明已离场，也不据此自动处罚实际占座。 |
| <a id="BR-16"></a>BR-16 | 统计口径 | 统计按授权场地、当地日期和快照时间计算；详见第4.3节统计指标与计算口径。登记使用率不等于物理在座率，分母为零显示“—”。历史违规撤销后重新计算净生效违规数，并展示快照时间。 |
| <a id="BR-17"></a>BR-17 | 个人信息 | 仅使用教学合成账号演示。用户可改本人显示名及通知偏好，不能改角色、学号标识、违规结论。账号启停由系统管理员处理；禁止禁用最后一名启用的系统管理员，或移除其系统管理角色。真实数据保存期限及校方授权未确定前不导入真实个人记录。 |
| <a id="BR-18"></a>BR-18 | 违规分层 | 自动事件或人工登记先进入待复核；授权复核者根据记录与材料决定生效或撤销。重复同一预约同一事件不得生成多条；无预约的现场事件须有场地、被登记者、时间和事实材料。生效后申诉撤销保留原结论历史。 |
| <a id="BR-19"></a>BR-19 | 故障免责与补偿 | 故障事件含起止、影响场地和受影响功能，经授权核实后关联违约。签到截止落在已核实的签到故障区间时，默认撤销该爽约违规并纠正关联限制；区间外由材料复核。客户端超时本身不能证明服务端故障。撤销处罚不恢复旧预约。 |
| <a id="BR-20"></a>BR-20 | 投诉闭环 | 投诉类型为设施、服务或违约申诉；学生只能查看本人，处理人限授权场地。待受理→处理中→已答复→已关闭；提交成功后，问题类型和原始说明只读；已答复时学生可通过独立输入框补充材料并返回处理中，原投诉与答复保留。学生也可确认关闭，不自动静默关闭。被投诉人回避处理；无其他管理员时升级给获得业务复核授权的系统管理员。已有投诉处于任何状态均不阻止学生就其他问题新建投诉；各投诉独立编号，说明、答复、补充和状态分别保存。本人可切换查询历史记录，关闭后原记录保留。 |
| <a id="BR-21"></a>BR-21 | 评价 | 每个本人已签到且已完成预约最多一条评价，评分1—5且文字不超过500字；修改保留历史。展示房间聚合评分和条数，默认不公开个人评价及行踪。管理员因不当内容隐藏文字要给理由，隐藏不改变评分；评价与投诉各有用途。 |
| <a id="BR-22"></a>BR-22 | 黑名单 | 本期由授权管理员以至少一条生效违规为依据登记限制，写明场地范围、开始与结束、理由。当前时间处于[限制开始,限制结束)时有效，过期不依赖后台任务。可提前解除。关联依据全部撤销则同步解除；仍有有效依据时由复核者决定保留或调整并说明。既有预约不自动取消；限制只能阻止新的预约。 |
| <a id="BR-23"></a>BR-23 | 十秒刷新 | 统计页可见时，每10秒尝试刷新；前次未完成则跳过本次，避免重叠。失败展示上次成功数据和“更新失败”；不得更新为成功时间。切场地或晚到响应用请求序号校验，旧响应不覆盖新结果。恢复前台立即刷新。此刷新不构成预约成功保证。 |
| <a id="BR-24"></a>BR-24 | 通知 | 业务成功即写入通知待发送记录；站内通知按业务事件和接收者去重。发送失败重试并显示投递状态，用户仍可从本人记录查结果；不依赖短信或外部消息服务。 |
| <a id="BR-25"></a>BR-25 | 到座导引 | 仅使用已核对的场地地图。用户选择出发入口作为起点；不显示持续跟随用户的定位点。目标为本人当前预约座位，路径沿场地配置中的可通行区域计算最短距离；可从桌排上方或下方的通道绕至侧面到座，不把座位当作通路。切换入口时自动重新计算，无路径时显示求助。地图缺失时返回楼层、房间和座位文字位置，不生成虚构路线。 |
| <a id="BR-26"></a>BR-26 | 推荐条件与排序 | 必要条件包含完整时段、开放、无重叠保留及所选正常设施；无有效地图时不以路线距离排序。偏好采用用户选择的靠窗优先或距离起点较近；距离按实际可通行路线长度计算，不以直线距离或转折点数量代替；同分按座位号稳定排序。故障设施不满足“必须可用”；无匹配时逐项提示，不自动放宽。推荐不占位，提交仍重新校验。 |
| <a id="BR-27"></a>BR-27 | 报告与核实 | 现场问题复用投诉的待受理、处理中、已答复、已关闭流程，保留发生时座位、预约、原文与补充。占座报告在原签到截止前受理时，对仍在报告座位待签到的预约提供一次保护，截止为受理后 30 分钟与预约结束中较早者；保护期间仍可换座和签到。未签到且保护到期时免罚释放；核实不属实则恢复原截止，若已过原截止且仍未签到，记录待复核爽约，已释放的座位不重新占用。相同操作键去重；报告不自动生成生效违规，不自动将座位全局停用。已核实不能使用的座位由管理员执行停用；物品与人员由现场人员处置。 |
| <a id="BR-28"></a>BR-28 | 换座资格与时段 | 仅本人待签到或使用中的有效预约可以关联现场问题申请换座，限同房间。暂离中须先返回；已终止或过有效签到截止的待签到预约拒绝。换座保留原编号、结束时间、签到截止（含已生效的占座保护）和规则版本，不重置宽限。剩余时长不足30分钟可继续原预约换座，不用于创建新的短预约。已生效的新预约限制不追溯剥夺原有效预约的剩余时段。 |
| <a id="BR-29"></a>BR-29 | 换座一致性与额度 | 目标必须覆盖待签到预约完整未使用时段，或使用中预约自切换时刻起的剩余时段，并满足必要条件。本人确认时再次校验当前预约版本、目标资源和条件版本。旧保留分段结束、新分段建立、换座记录和审计整体成功或均不生效；失败保留原预约。成功不新增预约次数或时长额度，不延长结束时间，不新增可评价次数。待签到仍待签到，使用中仍使用中；登记使用按座位分段，切换时刻不重复统计。 |
| <a id="BR-30"></a>BR-30 | 资源变更与问题独立性 | 部署前检查座位标识唯一、入口有效、通道连接与实际布局一致；设施故障由授权人员核实，修复不自动撤销独立停用。换座成功不关闭原现场问题；问题尚未关闭时，报告者的替代候选持续排除发生问题的原座位。管理员确认仍存在故障或占用时，须登记设施状态或按停用流程处置；未经恢复核实，不得仅因学生换座就清除已确认异常。未核实的报告不直接改变全局可用性或认定他人违规。 |

### 5.4 关键边界决策

|---|---|---|---|
| 创建预约 | 账号启用、无适用限制、额度足够，目标时段开放且同座及同用户均不冲突 | 拒绝创建，返回具体原因；原有预约不变 | BR-01—05 |

## 6. 行为与状态

### 6.1 核心业务流程

管理员维护资源和开放安排，核实设施状态；导航读取已核对的场地布局。学生设定时段与必要条件，按偏好查看候选及理由；提交时系统重新检查资格、区间冲突、额度和必要设施，成功后生成唯一预约。学生从当前预约打开到座路线，选择入口，到达后扫描桌面二维码，在窗口内通过校验并签到，离开时签退；系统处理未签到和预约到期事件。预约提交过程见[ACT-01](附件/01图模型/ACT-01-预约提交活动图.svg)。

遇到占座或设施问题时，学生从当前预约提交现场情况，查看处理进度，也可自主选择同房间替代座位。确认时系统再次校验并整体更新保留与使用分段，成功后更新当前座位和路线，失败保留原有效预约；原问题继续由管理员核实和处理。流程见[现场问题与换座活动图](附件/01图模型/ACT-02-现场问题与换座活动图.svg)。

设施故障先区分是否影响座位整体使用；仅插座故障更新设施状态，确需停止使用时进入停用流程。管理调整通过停用流程处理，管理员先核对影响清单，再依据预约状态取消或关闭并通知。自动事件和现场登记进入违规复核，投诉和申诉提供材料补充与答复渠道；生效违规才可成为限制依据，错误结论纠正时同步处理相关限制。

### 6.2 预约状态及资源占用

| 状态 | 进入条件与业务含义 | 时段保留及后续动作 |
|---|---|---|
| 待签到 | 预约创建成功，尚无有效签到 | 保留预约时段；可在开始前取消、窗口内签到或按条件换座；换座后仍待签到，原签到截止不变；截止后转爽约 |
| 使用中 | 到场登记成功 | 保留剩余时段；可按条件换座并保持使用中，或签退、到期结束、经现场确认后停用关闭 |
| 暂离中 | 本人在使用中发起暂离 | 保留至暂离截止或预约结束；依据最晚返回时间与预约结束时间的先后关系返回或结束 |
| 已取消 | 本人提前取消，或场地停用免罚取消 | 释放保留时段；保留原因和规则版本；不可重新签到 |
| 已完成 | 主动签退或预约到期结束 | 释放剩余时段；记录结束方式；满足资格后可评价 |
| 已爽约 | 截止时仍未签到 | 释放时段并生成待复核事件；不直接形成黑名单 |
| 异常关闭 | 立即停用或暂离超时等非正常结束 | 释放时段并保留原因；是否免罚或需复核按具体规则处理 |

主状态见[SM-01](附件/01图模型/SM-01-预约主状态图.svg)，暂离分支见[SM-02](附件/01图模型/SM-02-暂离状态图.svg)。后四类状态为预约终态，恢复资源不恢复旧预约。创建失败不产生占用资源的预约记录。

### 6.3 投诉、违规与限制的关系

投诉及关联预约的现场问题均经过待受理、处理中、已答复和已关闭；换座不关闭原现场问题。学生在已答复阶段补充材料时返回处理中，原答复保留；关闭后新问题通过新投诉引用原编号。流程见[SM-03](附件/01图模型/SM-03-投诉状态图.svg)。

违约事件经过待复核后生效或撤销，生效结论也可在申诉成立或故障核实后撤销。流程见[SM-04](附件/01图模型/SM-04-违规状态图.svg)。投诉状态不代替违规结论，违规结论不直接等于限制状态：限制还需独立的依据集合、场地范围、起止时间和解除记录。

### 6.4 状态转换规则

下面的转换表按预约、投诉和违约记录分别列出当前状态、触发操作、允许条件及处理结果。ST、CT、VT分别是三类转换的查找编号。拒绝请求和重复请求返回原结果时，状态保持不变。

签到与超时、取消与停用等操作发生竞争时，系统根据一致的当前状态与服务端判定时间决定结果。每个业务事件只提交一次合法转换，写入失败不能形成部分释放或重复违规。

### 6.8 竞争操作与失败处理

请求先验证身份、操作权限、对象范围及输入格式，不合格时立即拒绝且不触发业务补处理。合格请求取得一致当前状态后确定服务端判定时间，补处理已到期状态，再判断本次状态动作是否合法。最晚返回时间与预约结束时间相同时到期完成优先于暂离超时。停用需原子校验与提交；截止已过的预约先按到期规则处理，再应用合法停用操作。故障免责通过违规及限制纠正完成，不篡改实际预约时间线。两项竞争操作由最终提交顺序决定，第二项读取最新结果后拒绝或返回幂等结果。

越权或输入校验失败均不得产生业务副作用。合格请求遇到已到期对象时，可先完成独立的到期转换并返回最新状态，再拒绝原动作；原动作的拒绝本身不再修改业务数据。必要的失败审计不算状态变更。被取消、已完成、已爽约、异常关闭均不允许再次签到，恢复座位也不改变这些终态。

### 6.9 到座与现场换座流程

预约详情使用当前座位查找地图目标，用户指定起点后查看路线。起点变化或预约换座后，旧路线失效，重新展示当前目标。查看路线、核对座位码和报告现场问题均不代替签到，不改变预约的开始、截止或结束时间。

现场问题采用投诉状态流程，换座采用独立的资源变更操作。学生可保留原预约等待处理，也可确认替代方案。换座与签到、取消、签退、到期、停用竞争时，以已提交的最新预约状态校验；不允许同时保留两个重叠座位，也不允许失败后丢失原保留。失败不撤销已合法发生的独立到期转换。

### 7.1 测量口径与测试数据

查询与预约时延分别统计，记录从请求发送到明确结果返回的端到端耗时。业务拒绝、系统错误和超时分别计数；超时单列，不能仅删除失败请求后报告较低时延。P95按排序样本的向上取整0.95×样本数位置取值，并同时提供样本总数、成功率、错误数和测试环境。

并发正确性验证与性能指标分开。对于全部两两重叠、竞争同一座位的请求，在无其他故障时仅允许一个成功；对于仅部分成链重叠的区间，可能存在多个互不重叠的成功预约，应逐对验证最终有效区间。相邻区间按半开区间规则可同时成立，验收按区间关系判断每条请求的结果。

统计正确性使用独立样例手算：四座各开放60分钟，停用并集30分钟，登记使用90分钟，则可用座位分钟为210，登记使用率为42.9%。样例明细见[第8.4节统计计算样例](#fixtures)，并发与故障检验方法见第8.5节。

### 7.2 改进效果的对照评价

效果评价选用目标场馆实际采用的指引和操作方式作为对照，记录平台版本、场馆布局和任务条件。选择未参与页面设计的同学，分别完成找座、必要设施选座和现场问题处理任务，交替安排两种方式的使用顺序，并使用难度相近的不同座位任务减轻重复学习影响。记录成功完成数、耗时、走错次数、求助次数、重复输入和主观理解问题。

本期原型走查用于发现流程及信息理解问题；合成地图任务的结果不等同真实场馆寻路效果。实地找座比较须取得并核对场地图、入口和标识；现场冲突比较使用事先安排的演练，不干扰真实使用者。报告逐任务列出原始记录、失败原因和样本条件，不能用未经测量的提升百分比或少量参与者推断所有高校。

管理侧比较使用相同的设施故障及修复任务，记录需要修改的数据位置、操作耗时和遗漏；核对预约选座、推荐及管理页面的设施状态是否同步。原始记录包含任务条件、使用方式、结果、耗时、问题及证据，分别比较同类任务，不合并不同任务的时间平均值。

功能验收首先检查路线合法性、必要条件匹配和换座一致性；体验评价再检验是否减少步骤或时间。如未改善，则根据问题调整导引或流程，不预先宣称优于成熟平台。

### 8.4 统计计算样例

样本日期为2026-10-24，是合成演示日期；统计快照设为15:00，窗口14:00—15:00。R1有A01—A04四座，均开放60分钟。A03停用14:30—15:00，其余无停用。U01在A01登记使用14:00—15:00共60分钟；U02在A02登记使用14:00—14:30共30分钟。无暂离及其他使用。

因此可用座位分钟=4×60−30=210；登记使用分钟=60+30=90；登记使用率=90÷210×100%=42.857…%，显示42.9%。R2无开放座位，使用率显示“—”。该数据集用于验证统计公式及显示结果。另设独立换座样本：14:00—15:00连续登记使用，14:20由A01换到A05，则A01计20分钟、A05计40分钟，合计仍为60分钟；重复请求不新增分段或分钟。

### 8.5 并发与故障检验方法

使用屏障同时启动20个合格账号的创建请求，覆盖相同、部分重叠、包含和相邻时间区间；记录每个请求键及结果，再读取全部有效保留区间逐对检查。每种冲突情境重复50轮，对于同一座位上全部两两重叠的请求，在资格均满足且无其他系统故障时，恰有一个成功。链式相交区间允许多个互不重叠的预约成功，例如14:00—15:00与15:00—16:00可以同时成立，而14:30—15:30不能与任一前述预约同时成立；验收以最终有效区间逐对不重叠为准。相邻请求可同时成功。另用同一账号不同座位检查BR-03。该检验必须通过真实服务和存储执行，验收结果包含服务响应与最终存储记录。

故障检验分别在写入前、提交后响应前、通知发送时、后台暂停恢复时注入失败。比对预约、占用、审计、违约和通知记录，确认没有部分提交和重复事件。统计用独立手算样例核对，而非仅对比同一段程序的两份输出。

本期参数与边界见第5.2节，数据保存要求见第4.4节；签到、暂离、停用、预约限制和投诉回避按第5章规则执行。确认情况见[需求分析质量验证报告“关键事实与业务规则确认”](A-需求分析质量验证报告.md#confirmation)。原范围采用2026年10月28日确认的需求设定；2026年10月30日纳入到座导引、推荐及现场换座改进，场地实测信息和试用结果按实际活动补充；真实数据接入及实际业务处罚须另行取得相应授权。

### 9.2 后续开发可行性与迭代计划

后续研发按约8周、四个两周迭代组织。启动前核对人员投入、地图资料和管理条件，将新增功能与原有功能共同分解为开发和验证工作项，并估算工时。第8周保留整体检查、缺陷修正和交付时间。

| 迭代 | 时间 | 工作重点 | 交付成果 |
|---|---|---|---|
| 第1轮 | 第1—2周 | 身份授权、资源及预约基础 | 设计、环境、资源开放、预约创建及地图设施数据准备 |
| 第2轮 | 第3—4周 | 使用流程及停用处置 | 使用及停用流程、二维导引、条件推荐及P0验收记录 |
| 第3轮 | 第5—6周 | 违规处理、反馈、统计及暂离 | 暂离、反馈与统计；现场问题和本人确认换座 |
| 第4轮 | 第7—8周 | 综合验证与交付复核 | 并发和故障测试、可用性记录、缺陷复验、部署及交付材料 |

#### 第1轮：资源与预约基础

- 完成账号角色、资源、预约、地图及设施状态的数据关系和接口设计，建立可运行环境；先核对一个试点房间的位置与通道，形成可扩展到多房间的数据结构。
- 实现FR-01—05、FR-11、FR-14的基础路径，将区间冲突、幂等和对象权限纳入首轮验证。
- 退出条件：可演示授权查询与预约创建；执行AC-01—04、AC-17及AC-24已实现分支，记录未完成分支。

#### 第2轮：使用、到期与停用

- 完成FR-06—13，验证统一时钟、截止等号、重复任务和资源释放。
- 实现停用影响预览、现场确认、免罚处置和恢复不复活；并行完成FR-25、26、29的地图、导引和条件推荐基础路径，检查入口选择、路径距离及设施故障对结果的影响。
- 退出条件：P0完整可演示，执行AC-05—09、AC-13—15、AC-19、AC-21及权限回归；所有阻断缺陷明确修复责任。

#### 第3轮：违规处理、反馈与统计

- 完成FR-15—24，实现暂离、返回和超时释放，贯通手动事件、复核、申诉、限制及故障纠正，补齐个人资料、评价和站内通知。
- 完成FR-27、28，将现场问题与投诉处理衔接，实现同房间换座及失败保留；完成统计刷新；组织同学对导引、推荐和换座原型进行走查。
- 退出条件：P0、P1功能均完成；执行AC-10—12、AC-16、AC-18、AC-20、AC-22—34，回归相关状态与权限路径。

#### 第4轮：综合测试与交付

- 第7周冻结必需功能范围，执行QR-01—13和全部本期AC，并完成独立使用分段统计及换座竞争检查，记录环境、原始结果、问题及修复复验。
- 第7周结束前，各成员向A（俞烨涛）提交演示、测试记录、缺陷清单及文档；第8周前半修复阻断问题，后半组织安装复现和材料一致性检查。
- 最终提交前至少保留两个工作日用于整体检查及修正，停止新增功能，集中复验P0、P1需求及跨模块流程。

每轮均包含测试与演示。出现进度风险时，先简化装饰和实现方式；涉及P0、P1范围改变时须记录原因、受影响功能及验收标准，由A（俞烨涛）组织范围和可行性评估后更新需求基线。具体技术方案在设计阶段确定，优先选择小组能部署、维护和验证的单体应用与存储方案。

### 9.3 开发工作项与进度跟踪

每轮开始时，A（俞烨涛）将相关FR拆为设计、实现、测试或修复任务，明确依赖关系和验收条件。任务至少记录编号、关联FR与AC、负责人、复核人、计划周次、预计工时、实际工时、状态和产物链接。负责人结合可投入时间估算工时，并在执行过程中登记实际投入和阻塞原因。

工作项状态采用“待开始、进行中、待复核、已完成、受阻”。任务完成时，对应产物应能够查看或运行，约定检查已经执行，结果和遗留问题有记录，并由复核人给出结论。A（俞烨涛）每周检查进度和范围变化，每两周组织迭代演示与回顾，同时负责整套需求分析成果的检查、优化与升级。

A（俞烨涛）负责接收并逐项审查B（刘洁）、C（钱瑾）提交的初版需求分析，对照课程要求识别缺项、歧义及不一致，组织并承担需求正文、业务规则、数据定义、状态及其他图模型、交互原型、验证材料和配套报告的系统性修改、优化与升级。同时，A（俞烨涛）负责统一两项目的文档结构与质量标准，协调任务和依赖，跟踪问题修正，管理版本及变更，并组织最终材料整合与提交前复核。

B（刘洁）负责自习室需求及业务规则，核对范围变更和需求追踪；C（钱瑾）负责状态模型、原型与验证，核对状态一致性和验收覆盖。D（何沐）、E（金施成）分别主责智能问答项目的需求及模型验证，并按安排参加自习室项目的交叉复核。各成员的责任与已有产物记录见[需求分析质量验证报告“成员贡献与责任”](A-需求分析质量验证报告.md#contribution)。最终交付依据为已批准范围内的功能、质量及文档验收结果。

AI辅助范围包括资料整理、需求审查、遗漏与冲突检查、文档静态检查和阅读效果检查。业务规则、功能范围、方案取舍、人工走查和验收结论由相应负责人决定，A（俞烨涛）统筹成果检查与优化。

任务记录采用“TASK-序号”编号，用于查找对应的工作任务及交互记录。本报告按记录顺序编为TASK-01—TASK-10。

### B.2.1 TASK-01 图模型标注与原型重构

2026年10月28日，A（俞烨涛）提供8张截图，指出图中说明与原型布局问题。关键请求原文包括：“这些奇奇怪怪的标注你看看，如果不需要就请你删去”“找个地方标注一下1和0..*是什么意思”“排版、各方面请你检查一下，上网学习一下别人的原型，重新设计一下”。

AI查阅Ant Design官方列表、表单、导航规范及TDesign Starter介绍，同步修改图源与SVG，精简说明性标注，重构页面布局与角色导航，并补充暂离交互。官方参考及当前交互范围见[原型说明](附件/02原型/原型说明.md)，模型修改位置见[质量验证报告的问题处理记录](A-需求分析质量验证报告.md#issues)。

### B.2.4 TASK-04 公开依据核对与业务改进

| 记录项 | 内容 |
|---|---|
| 日期与发起人 | 2026年10月29—30日；A（俞烨涛） |
| 人工提出的问题 | 既有系统已较成熟，需要说明重新研发的价值；指出首次到场找座、未预约占座等问题，要求联网核实且先讨论再修改 |
| 实际提示摘要 | 要求资料真实、有依据；在方案讨论后明确要求“那请你进行完善和改进需求分析那些文件吧” |
| 工具工作 | 查阅官方公开资料，区分事实、已有产品能力与方案建议；在副本内同步需求、用例、规则、模型、原型、走查表和追踪关系 |
| 方案取舍 | 采用二维到座导引、设施条件推荐及本人确认换座；不承诺连续定位和自动识别占座，不将三维展示列为必需交付 |
| 核对范围 | 官方资料定位、编号与链接、跨文件一致性、图形与原型交互、Word分页；效果对比需后续参与者和场地记录 |
| 产物 | V2.5需求规格说明书、配套报告、图模型、交互原型及走查表 |

本次任务约束为保留原有功能、在指定项目范围内修改、保留原版副本、不得编造访谈或测试结果，新增规则与历史确认分开登记。具体来源与适用限制见需求规格说明书第10章。

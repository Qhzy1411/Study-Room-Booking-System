# 静阅 · 智慧自习室预约与管理系统

学生可以按时段和设施要求选座，到场后扫描座位上的二维码签到。遇到占座或设施故障时，可以报告现场问题并申请换座。场地管理员负责排班、座位检修和现场处理，也可以查看各时段的预约量与座位使用率。

## 本地运行

项目使用 Node.js、Express 5 和 SQLite，浏览器页面由同一服务提供。请安装 Node.js 22.5 或以上版本及 pnpm 9 或以上版本，在项目根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm start
```

启动后打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。首次启动会自动初始化演示数据，后续启动沿用 `data/studyroom.db` 中的记录。需要重置演示数据时再运行 `pnpm seed`，该命令会清空当前数据库并重新写入样例。

### 演示账号

以下账号的初始密码均为 `123456`。

| 账号 | 角色 | 可查看的业务 |
|---|---|---|
| `u01`、`u02`、`u03` | 学生 | 预约、签到、换座、投诉与评价 |
| `m1` | 场地管理员 | 图书馆二层的排班、座位和现场记录 |
| `m2` | 场地管理员 | 图书馆三层的排班、座位和现场记录 |
| `s1` | 系统管理员 | 账号、授权、规则、审计与统计 |

用 `s1` 调整演示时钟后，系统会为两个楼层补齐跳转日期前 6 天和当前预约窗口内缺失的开放计划。学生可按调整后的日期查询和预约，管理员可在“场地与资源”中核对排班。已有开放计划保留。

初始化会为两个楼层生成其他学生在当天的预约，以及过去 7 天的历史预约和使用记录。统计页选择初始化日期的前一天即可查看完整的七日使用率趋势。

## 运行测试

```bash
pnpm test           # 运行全部自动化测试
pnpm test:unit      # 服务端业务接口与前端组件
pnpm test:e2e       # 浏览器端到端测试，使用本机 Chrome 或 Edge
pnpm test:coverage  # 生成覆盖率报告
```

服务端接口测试使用临时 SQLite 数据库。需要准备性能测试样本时，可将 `DB_PATH` 指向单独的测试库，再运行 `pnpm seed:perf`。该命令会重置目标库并生成含 500 个座位、1 万条历史预约的样本场地。
